# UIForge — notes for Claude

Figma-like desktop tool for game UI layout (Electron + Vite + React + TypeScript + PixiJS v8 + zustand/immer + ag-psd).
User speaks Vietnamese; reply in Vietnamese.

## Commands
- `npm run build` then `env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron .` to launch the built app.
  VS Code terminals set `ELECTRON_RUN_AS_NODE=1`; always unset it or Electron runs as plain Node.
- `npm run typecheck` (TypeScript 7; `baseUrl` is not allowed, paths are relative).
- Headless testing: env vars `DM_OPEN_PSD`, `DM_PROJECT`, `DM_SCRIPT` (JS file executed in the renderer via executeJavaScript,
  `window.__dm` exposes store + helpers, see `src/renderer/src/debug.ts`), `DM_SCREENSHOT`, `DM_SCREENSHOT_DELAY`, `DM_EXIT_AFTER=1`, `DM_LOG_CONSOLE=1`.
  Test PSD generator: `.tmp/make_psd.mjs` (ag-psd writePsd with imageData, no canvas needed).

## MCP / automation bridge
- App listens on `http://127.0.0.1:47821` (`DM_BRIDGE_PORT`): `GET /health`, `POST /rpc {method, params}` → `src/main/bridge.ts` → IPC → `src/renderer/src/bridge.ts` handlers.
- MCP server: `mcp/server.ts` → built by `npm run build:mcp` to `out/mcp/server.js` (esbuild, alias `@` → renderer src, only pure modules: model/, export/).
  `.mcp.json` registers it for Claude Code. Falls back to reading/writing `project.json` when the app is not running.
- Modules imported by the MCP server must stay free of DOM/Pixi imports (`model/naming.ts` exists for that reason).

## Conventions
- Document model in `src/renderer/src/model/types.ts`. Coordinates: top-left origin, Y down, node x/y relative to parent.
  `children` arrays are bottom-to-top (last = on top); the Layers panel shows them reversed.
- Anchor/pivot stored in editor convention; conversion to Unity happens only in `model/anchors.ts` (`toUnityRect`), documented in `docs/LAYOUT_SPEC.md`.
- Store mutations go through `update`/`updatePage` (immer). Drags: call `snapshot()` once at drag start, then mutate with `{ history: false }`.
- `indexPage(page)` is cached per page object (WeakMap); inside immer drafts use `locate()` from `store/editor.ts` instead.
- Scene sync (`canvas/sync.ts`) skips nodes whose object reference is unchanged; never mutate nodes in place outside immer.
- Pixi needs `import 'pixi.js/unsafe-eval'` first (CSP forbids eval).
- Never call `app.destroy(true, …)` on a secondary Pixi Application (Present, render.ts): `true` releases Pixi's global batch pool that the main viewport still uses → `Cannot read properties of null (reading 'clear')` on the next frame. Use `app.destroy({ removeView: true }, { children: true })`.
- Assets: bytes cached in `store/assets.ts`; on disk at `<project>/assets/<file>.png`; asset id = first 16 hex of sha256(png).
- Group bounds are re-fitted after every mutation (`fitAllGroups`), so group x/y/w/h always equal the union of children.
- Hover state is in `store/hover.ts` (not the editor store) so mouse moves never re-render panels; the Layers panel is virtualized (`LayersPanel.tsx`, ROW_H=26) with memoized rows. Pixi renders on demand (`app.ticker` stopped; `render()` calls `app.render()`), so anything that changes visuals asynchronously must call `requestRender()` (textures do via `onTextureLoaded`).
- Theme: `store/theme.ts` (`auto|light|dark`, CSS vars on `:root[data-theme]`, `canvasPalette()` for Pixi colours).
- Keyboard shortcuts: every action is a `Command` in `ui/commands.ts` (user overrides in localStorage `uiforge.keybindings`); `ui/shortcuts.ts` only dispatches. Add new shortcuts there, not as ad-hoc key handlers.
- Layer styles: image nodes keep `sourceAssetId` (raw pixels) + `effects` (ag-psd `LayerEffectsInfo` JSON) + `contentOffset`; `psd/restyle.ts` re-renders through `psd/effects.ts` when edited. Patterns live in `doc.patterns` as PNG assets. Never mutate `effects` without calling `scheduleRestyle`. Text nodes with `effects` are rasterized (`canvas/textRaster.ts`) and pushed through the same pipeline in `sync.ts`; groups re-render their `(style below/above)` child images via `restyleGroup`. The Layer Style UI is `ui/LayerStyleDialog.tsx` (Photoshop layout).
- Components: masters are frames/groups with `component: {name}` (also listed in `doc.components`); `InstanceNode` children are DERIVED — regenerated by `model/instances.ts::expandInstances` in the store's post-mutation pass (ids `<instanceId>:<masterChildId>`, `meta.instanceOf/fromInstance`, locked). Never edit instance children directly; `setNodeProps` on them is redirected to `overrides` (text/visible/assetId).
- Auto layout: `model/autoLayout.ts::applyAutoLayouts` runs before `fitAllGroups` in the post-mutation pass; node x/y are therefore always the laid-out result (export needs no layout engine).
- Image edits (`node.edits`, crop/flip/rotate/adjustments) are non-destructive: `psd/restyle.ts::applyImageEdits` re-renders from `originalAssetId` (fallback `sourceAssetId`) before layer effects. Crop is in original-image pixels.
- Prototype flows: `model/flows.ts` (pure) holds trigger/action/transition catalogues, `normalizeConnection` (migrates legacy `overlay:boolean` / `slide-*`), easing and overlay placement; the player is `ui/Present.tsx` (`Presenter`: base layer + overlay stack + history, exposed as `window.__dmPresenter` while presenting); editing UI in `ui/PrototypePanel.tsx`; canvas arrows/labels in `Viewport.tsx` (prototype mode). Connections are normalized in `setDoc`; a hotspot may have several connections (one per trigger/key).
- Rule-based anchoring is pure (`model/autoAnchor.ts::suggestAnchors/applyAnchorSuggestions`), applied by store `autoAnchor()`; only touches top-level frame children with default anchor unless `overwrite`.
- Device simulation (`model/simulate.ts`) is pure (used by MCP too): CanvasScaler + anchor math, `DEVICE_PRESETS`, `simulateFrame` → `frameForSim` for rendering. Sprite atlas planning is pure (`export/atlas.ts::planAtlas`), sheets are drawn in `store/project.ts::exportLayout`. Unity capture diff lives in `canvas/compare.ts` (renderer only, uses canvas).
- Unity scripts in `docs/unity/`: runtime `UIForgeNodeRef.cs`, `UIForgeSafeArea.cs` (Assets/UIForge/), editor `UIForgeLayoutImporter.cs`, `UIForgeSync.cs`, `UIForgeCapture.cs`, `UIForgeVerify.cs` (Assets/Editor/UIForge/). Batch test project: `.tmp/unityproj`.
- Autosave: `store/autosave.ts` writes drafts to `<project>/.autosave/` (or `<userData>/autosave/untitled/` with assets) every 30 s while dirty; `offerRecovery` runs in `autoOpenLast`/`openProject`. Headless tests set `DM_NO_RECOVERY=1` (no dialog, no timer) and `DM_AUTO_DIALOG=<idx>` to auto-answer dialogs. Tests only use `.tmp/_testproj*` folders.
- Component states: `model/states.ts` (pure): direct children of a master named normal/hover/pressed/disabled/selected; store `addState`/`showState`; export `component.states`; atlas names `<frame>_<button>_<state>` (`export/atlas.ts::atlasSpriteName`).
- Game link (HTML5 games ↔ app): pure rules in `model/game.ts` (`mergeGameDesign` upserts pushed screens by `meta.gameId` / frame `meta.gameScreen`, baseline in `doc.game`; `diffGame` → `GameChanges`; `rebaselineGame`; `setNodeArt`/`replaceGameSource`), renderer side `store/game.ts` (asset loading, replace, `syncGame` writes into `<root>/uiforge/`, `runGameAgent`), UI `ui/GamePanel.tsx` (left tab "Game" + Sync window). Capture runs in main: `main/capture.ts` (hidden BrowserWindow + DevTools protocol for a viewport of the design size — load about:blank BEFORE any emulation command or Electron crashes; blob→URL tracking script so Phaser textures map back to files; screenshots via `capturePage` (~30 ms, honours the emulated size) — `Page.captureScreenshot` on a hidden window takes ~3 s and is only the fallback; the window stays alive 4 min between captures and `syncGame` closes it so changed art is reloaded; `<game>/uiforge/asset-cache.json` maps file+mtime+size → assetId) + `main/extract.ts` (`extractInPage` is serialized with toString and run inside the game page: must stay self-contained). Headless game agent: `main/agent.ts` spawns `claude -p` (stream-json). Docs: `docs/GAME_LINK.md` (also served by MCP `game_guide`). Test game: `.tmp/testgame` (Phaser + DOM popup, `python -m http.server 3199`), scripts `.tmp/game_test1.mjs`, `.tmp/sns_capture.mjs`; the real games live in `F:/Youtube Playables/games/<name>` (their repo has `.mcp.json` → this server and skill `.claude/skills/uiforge`).
- Game components (`model/gameComponents.ts::prepareComponents`, pure): before a push, occurrences of shared widgets (element `component`, recipe rules `{name, match, code}`, earlier pushes via `priorComponents`, or detected by structure signature ≥2×) get `componentMap` and a pseudo-screen `__components` (frame "Components") holds one master per component (copies carry `origin` → art from the occurrence). `mergeGameDesign` marks masters (`component`, anchors via `masterAnchors`) and turns occurrences into instances (overrides by master game id; `size` when resized). Baseline elements of instances store `component` + `overrides`; diff reports master edits once (rect relative to the component) + per-instance overrides; `GameChanges.components` lists code + usage. Instances: `InstanceNode.size` = own box (children via `instances.ts::layoutByAnchors`: uniform → scale, else anchors), `fitGroup` skips sized instances; override `fontSize`.
- Canvas picking (`canvas/interaction.ts`): click goes through the top frame and wrapper groups (single child, or ≥ 75 % of the screen — deep DOM/Phaser captures), Ctrl/⌘+click = deepest layer (`deepestAt`, enters its parent scope), double-click enters a group skipping wrappers; instance parts (`meta.fromInstance`) are selectable but not movable.
- Pixel snap: `canvas/pixelSnap.ts` (localStorage `uiforge.pixelSnap`, command `view.pixelSnap` Ctrl+Shift+'); move snaps the selection's top-left to whole page px (after guide snapping, so pixels win), resize rounds edges in absolute px; Alt = free.
- Font epoch (`canvas/fontEpoch.ts`): sync skips text whose node/textKey is unchanged (re-opening a project keeps the same keys), so text drawn before a font arrived kept the fallback in the editor (verified; `render_frame` builds a fresh scene and was fine). A font that arrives after text was drawn (project fonts, captured webfonts, `document.fonts` loadingdone) bumps the epoch: every canvas font list ends with a fake family `uiforge-fonts-<n>`, text entries redraw when their epoch is stale, `CanvasTextMetrics` is cleared and the viewport re-renders. Capture copies the game's webfonts (`main/capture.ts::copyWebFonts`, rules read in `extract.ts::webFonts`) into `<root>/uiforge/fonts/<family>.<ext>`; `pushGameDesign` reloads project fonts.
- Fonts: `store/fonts.ts::exportFontFiles` writes `export/fonts/` from `queryLocalFonts().blob()` (system) or `<project>/fonts` (project); layout `text.fontFile`. Unity: `docs/unity/UIForgeTmp.cs` (reflection, no compile dependency on TMP), `UIForgeFlowRunner.cs` (runtime prototype), importer menu `UIForge > Import Page`. Unity test project has com.unity.textmeshpro + essentials; batch tests: `UIForgeBatchTest.Run` (one frame) and `UIForgePageTest.Run` (page).
